# fillBPAi — Projeto CLAUDE.md

## Sobre o Projeto
**Nome exibido: PonteBPA** (20/10/2026) — título da janela principal e do seletor de planilha, README e futuras janela "Sobre" e instalador. A troca é só visual: repositório, `artifactId`, pacote `br.gov.ses.fillbpai`, classes, métodos, arquivo do banco (`fillbpai.mv.db`) e a propriedade `fillbpai.hoje` continuam iguais. Não renomear código por causa do nome.

Aplicação desktop JavaFX que importa dados de atendimentos de saúde de planilhas Excel e gera arquivos magnéticos BPA-I (Boletim de Produção Ambulatorial Individualizada) no formato exigido pelo DATASUS/Ministério da Saúde.

O Núcleo de Telessaúde de MS utiliza esta aplicação para importar dados de atendimentos no sistema SIA/SUS. O formato BPA-I tem layout posicional rígido (353 chars por registro, incluindo CRLF — layout 2026, ver `data/Layout_Exportacao_BPA_2026.pdf`).

## Stack
- Java 21, JavaFX, JPA/Hibernate (sem Spring Boot)
- H2 Database (embarcado, `hibernate.hbm2ddl.auto=update` — persiste dados entre reinicializações)
- Apache POI para leitura de `.xlsx`
- Maven para build

## Estrutura do Projeto
Arquitetura em camadas: `controller → service → repository → model`, com `util`, `dto` e `ui`.

### Modelo de Dados (normalizado)
- `Paciente` — chave natural: CPF (único). Paciente sem CPF ("Paciente sem CPF" = Sim, CPF vazio) recebe uma chave interna `SC` + 12 caracteres derivada do **CNS** (`CpfUtils.chaveSemCpfPorCns`: CNS em base 36 — recomendação 68, 19/10/2026; o CNS é obrigatório e válido nesse caso), estável entre reimportações. A chave antiga, por nome + nascimento (`CpfUtils.chaveSemCpf`), juntava homônimos nascidos no mesmo dia e separava grafias diferentes da mesma pessoa; pacientes gravados com ela são migrados na importação (`AtendimentoImportacaoService.migrarChaveSemCpfAntiga`), só se o CNS gravado for vazio ou igual ao da linha (CNS diferente = homônimo, ganha cadastro próprio); a chave nunca vai para o BPA-I (gerador e tela tratam como CPF vazio — `CpfUtils.isChaveSemCpf`). @OneToOne com Endereco. Campo `situacaoRua` é **legado** desde 16/10/2026 (não é mais atualizado): a situação de rua passou para o atendimento; o valor do paciente só serve de reserva para atendimentos gravados antes da mudança.
- `Endereco` — 1:1 com Paciente. Inclui campo `codigoIbge` (7 dígitos).
- `Medico` — chave natural: CPF (único, obrigatório — linha sem CPF do médico é rejeitada). Campos: id, cpf, nome, cns. `cns` = último CNS conhecido do médico, usado como reserva quando a grafia do nome na linha não está em `medicos_cns.csv` (ver `CnsProfissionalUtils`). O CPF fica só no banco local — nunca no CSV, que é versionado num repositório público.
- `Estabelecimento` — chave natural: codigo (único). Campos: id, codigo, nome. Quando a célula "Estabelecimento" da planilha não traz um código reconhecido (formato esperado `"código - nome"`), a importação tenta vincular por nome a um estabelecimento já cadastrado (`EstabelecimentoRepository.buscarPorNome`); se não encontrar, o atendimento fica sem estabelecimento vinculado (`AVISO`, não bloqueia).
- `AtendimentoBPAi` — @ManyToOne para Paciente, Medico, Estabelecimento. Campos próprios: tipoServico, sigtap, dataAgendamento, horaAtendimento, especialidadeMedico, cboMedico, cidConsulta, cnsProfissional, cnesNts, codIne, folha / linhaFolha / remessaEm (folha, linha e data/hora da última remessa BPA-I em que o atendimento foi enviado — gravados na geração, 20/10/2026; nulos = não enviado), pacienteSemCpf ("S"/"N"/""/nulo — ver Geração BPA-I), situacaoRua ("S"/"N"/"" — situação de rua no momento do atendimento, 16/10/2026; planilha sem a coluna grava "N"; nulo só em atendimentos antigos).

### Validação Pré-Importação
Antes de importar, a planilha é validada por `ValidacaoPlanilhaService`. Se houver erros bloqueantes, a importação é **impedida** e um relatório de erros é exibido com opção de download em TXT. Avisos não-bloqueantes são exibidos em diálogo separado mas não impedem a importação.

`ErroValidacao` tem campo `severidade` (enum `ERRO`/`AVISO`) e método `isBloqueante()`.

Tipos de ERRO (bloqueantes):
- **CEP_AUSENTE** — CEP do endereço não informado. Também rejeitado pelo `AtendimentoProcessor` desde 16/10/2026 (antes só a análise bloqueava e a importação aceitava). Exceção (Decisão 25, 16/10/2026): com a coluna "Situação de Rua" = Sim, CEP vazio é o AVISO **CEP_AUSENTE_SITUACAO_RUA** ("o CEP será registrado em branco") e o BPA-I sai sem CEP; o município continua obrigatório (sem CEP, `MUNICIPIO_NAO_ENCONTRADO` diz "o paciente não tem CEP — verifique a grafia do município")
- **CEP_INVALIDO** — CEP presente mas com tamanho incorreto (diferente de 8 dígitos após normalização); com 7 dígitos a mensagem orienta formatar a coluna como texto (`CepUtils.mensagemTamanhoInvalido` — sem completar com zero, mesma decisão do CPF)
- **CEP_FALSO** — CEP com os 8 dígitos iguais (00000000, 99999999) — CEP de preenchimento (16/10/2026). Também rejeitado pelo `AtendimentoProcessor`
- **MUNICIPIO_AUSENTE** — célula do município vazia (valor "Paciente: X — município ausente"); sem o nome não há a primeira busca do IBGE. Também rejeitado pelo `AtendimentoProcessor`
- **MUNICIPIO_PELO_CEP** (AVISO) — município fora da tabela de MS, mas IBGE encontrado pelo CEP: mostra o município que o CEP indica ("\"Douradoz\" — CEP 78020000 → Cuiabá/MT"), para o usuário conferir. Nome oficial/UF pelo código IBGE via `IbgeUtils.nomeMunicipio` (tabela `dados/municipios_brasil.csv`, 5.571 municípios do IBGE). O mesmo aviso vai para o log de importação
- **MUNICIPIO_NAO_ENCONTRADO** — município fora da tabela de MS (`dados/municipios_ibge.csv`) **e** código IBGE não encontrado pelo CEP (CEPs do banco + APIs de CEP) — mensagem pede para conferir a grafia do município e o CEP. A análise faz a busca completa (usa a internet só para CEP novo; `MainController` pré-carrega os CEPs do banco via `AtendimentoImportacaoService.preCarregarCacheIbge`); a importação confere o IBGE de **todas** as linhas antes de abrir a transação (`AtendimentoImportacaoService.verificarIbgeDeTodasAsLinhas`) e, se alguma linha estiver sem município ou sem IBGE, **bloqueia a planilha inteira** sem gravar nada ("Importação bloqueada … nenhuma linha foi importada", com a lista de linhas) — linhas não são rejeitadas uma a uma. `IbgeUtils.buscarPorNome` tolera sigla da UF ("- MS", "/MS", "(MS)") e espaços repetidos
- **CPF_AUSENTE** — CPF do paciente não informado sem a coluna "Paciente sem CPF", ou com ela marcada Não (ou vazia/não reconhecida); não é erro só quando a coluna existe e vale Sim
- **CNS_OBRIGATORIO_SEM_CPF** — CPF vazio com "Paciente sem CPF" = Sim exige o CNS do paciente com exatamente 15 dígitos e dígito verificador válido (`CnsUtils.isCnsSemCpfValido`; motivo na mensagem via `motivoCnsSemCpfInvalido`) — o CNS é o documento do paciente no BPA-I nesse caso. Também rejeitado pelo `AtendimentoProcessor`; nesse caso o aviso `CNS_INVALIDO` não é repetido (decisão de 09/10/2026)
- **CPF_INVALIDO** — CPF presente mas com tamanho incorreto (diferente de 11 dígitos após normalização). Não se completam zeros à esquerda (não dá para garantir que o dígito que falta é um zero perdido pelo Excel); a mensagem orienta formatar a coluna como texto
- **CPF_FALSO** — CPF do paciente com os 11 dígitos iguais (00000000000, 11111111111...) — juntaria pacientes diferentes num só (o CPF é a chave do paciente)
- **CPF_CONFLITO_SEM_CPF** — CPF do paciente preenchido com a coluna "Paciente sem CPF" = Sim (informações contraditórias)
- **CPF_DV_INVALIDO** — CPF do paciente com dígitos verificadores errados (`CpfUtils.isDvValido`, módulo 11) — dígito digitado errado
- **CPF_MEDICO_DV_INVALIDO** — CPF do médico com dígitos repetidos ou verificadores errados — criaria um segundo cadastro do mesmo médico, com folha própria
- **DATA_AUSENTE** / **DATA_INVALIDA** — data de agendamento (= data do atendimento; define `prd-dtaten` e a competência) vazia ou em formato não aceito por `DateUtils.parse` (d/M/aaaa — dia e mês com ou sem zero —, aaaa-MM-dd, d-M-aaaa; ano sempre com 4 dígitos). Modo **estrito** desde 14/10/2026: data inexistente (31/02, 31/04) é recusada — antes virava o último dia do mês em silêncio. Outros nomes de cabeçalho para essa data entram como alias de `DATA_AGENDAMENTO` em Configurações
- **DATA_NASCIMENTO_AUSENTE** / **DATA_NASCIMENTO_INVALIDA** / **DATA_NASCIMENTO_INCOERENTE** — nascimento vazio (a idade sairia 000 no BPA-I — decisão de 14/10/2026), em formato não aceito ou inexistente, ou que não confere com o atendimento (`DateUtils.incoerenciaNascimento`: depois da data do atendimento, ou idade acima de 130 anos — limite de `prd-idade`). Mesma regra no `AtendimentoProcessor`
- **DATA_NASCIMENTO_SEM_ANO** (ERRO) / **DATA_ATENDIMENTO_SEM_ANO** (AVISO) — célula de data cujo formato de exibição não mostra o ano (`dd/mm`, `d-mmm` — `ExcelImportService.isDataSemAno`, flags `dataNascimentoSemAno`/`dataAgendamentoSemAno` no DTO). É o que o Excel faz quando se digita só dia e mês: grava a data com o **ano corrente** em silêncio — o paciente virava um bebê de meses (verificado em 14/10/2026). No atendimento é aviso, porque a coluna pode estar só formatada sem o ano. Mensagem: "Data de nascimento (15/03) não está no formato correto (dd/MM/aaaa)" — sem mencionar o Excel. As mensagens de data mostram `dd/MM/aaaa` (`DateUtils.formatar`), não o `aaaa-MM-dd` da célula
- **CID_INVALIDO** — célula do CID sem código CID-10 reconhecível ou com mais de um (`CidUtils.extrair`). Também rejeitado pelo `AtendimentoProcessor`. **CID_AUSENTE** (AVISO, decisão de 14/10/2026) — CID vazio, ou só com traço (`-`, `--`, `–`, `—` = "sem CID", `CidUtils.isSemCid` — 19/10/2026; antes era `CID_INVALIDO` e bloqueava); o BPA-I sai com o CID em branco. Também no log de importação
- **TIPO_SERVICO_AUSENTE** / **TIPO_SERVICO_INVALIDO** — tipo de serviço vazio ou diferente de Teleconsulta/Teleinterconsulta (únicos aceitos, por decisão). Vazio é aceito só para nutricionista/psicólogo (`EspecialidadeUtils.usaProcedimentoFixo` — procedimento fixo 0301010315 na geração), e nesse caso a análise indica a coluna vazia com o AVISO **TIPO_SERVICO_VAZIO_PROCEDIMENTO_FIXO** (valor = especialidade) e o `AtendimentoProcessor` registra o mesmo aviso no log de importação; para os demais, tipo vazio deixava o SIGTAP nulo (procedimento `0000000000` no BPA-I e duplicação na reimportação). Mesma regra em `AtendimentoProcessor.definirSigtap`/`codigoSigtap`
- **CBO_AUSENTE** / **CBO_INVALIDO** — CBO do médico vazio ou sem 6 dígitos depois de tirar a máscara (`CboUtils`: `2251-25` → `225125`). Vai para o BPA-I (`prd-cbo`, 6 posições); com máscara deslocava o registro inteiro. A importação grava só os dígitos e o gerador também normaliza (dados antigos)
- **ESPECIALIDADE_AUSENTE** — especialidade vazia; sem ela o atendimento sumia da árvore da tela e nutricionista/psicólogo não eram reconhecidos. A especialidade é gravada padronizada (`EspecialidadeUtils.padronizar`: sem prefixo "Médico", maiúsculas, espaços repetidos reduzidos; acentos mantidos), para "Cardiologia"/"CARDIOLOGIA" não virarem duas especialidades (dois nós na árvore, duas folhas)
- **CPF_MEDICO_AUSENTE** / **CPF_MEDICO_INVALIDO** — CPF do médico ausente ou diferente de 11 dígitos; também rejeitado por `AtendimentoProcessor` antes de gravar (antes, um CPF fictício maior que a coluna derrubava a transação da planilha inteira)
- **SEXO_AUSENTE** / **SEXO_INVALIDO** — sexo vazio ou não reconhecido (`SexoUtils`: F, M, I, Feminino, Masculino, Indeterminado, Fem, Masc, Mulher, Homem). Também rejeitado pelo `AtendimentoProcessor` (16/10/2026). Antes a análise não conferia: "Fem"/"Mulher" cancelavam a importação no banco (coluna de 1 caractere), "H"/"1"/"X" iam para o BPA-I e sexo vazio saía como F
- **RACA_AUSENTE** — raça do paciente não informada (campo obrigatório no layout do BPA-I, seq 21 prd-raca)
- **RACA_INVALIDA** — raça presente mas não reconhecida por `RacaUtils` (grafia incorreta, texto ambíguo como "Preta/Parda", negação como "Não Branca", "Indeterminado") — mensagem de `RacaUtils.mensagemNaoReconhecida`; "Negra/Negro" tem mensagem própria (o IBGE separa Preta e Parda — sem conversão automática, decisão de 13/10/2026)
- **ESTRUTURA_INVALIDA** — coluna obrigatória ausente do cabeçalho ou nome de coluna ambíguo (casa com mais de um campo canônico). O mapeamento olha também os dados (`PlanilhaColumnMapper.mapear(Sheet)`, usado pela análise e pela importação): sem coluna "Especialidade", a coluna "Especialidade/Médico" só é tratada como formato legado se ao menos metade das células preenchidas tiver o separador "ESPECIALIDADE - NOME"; senão `ESPECIALIDADE_MEDICO` conta como coluna obrigatória ausente (caso real: coluna da especialidade sem título e "Especialidade/Médico" só com nomes — antes gravava o nome do médico como especialidade e o médico sem nome). A tela de estrutura (`MainController.mostrarDialogoErroEstrutura`) lista também as colunas com dados mas sem cabeçalho (`colunasSemCabecalho`: letra da coluna + exemplo)
- **ESPECIALIDADE_MEDICO_SEM_SEPARADOR** — planilha legado (formato confirmado pelo conteúdo) com célula "Especialidade/Médico" sem o separador "ESPECIALIDADE - NOME"; também rejeitado pelo `AtendimentoProcessor.separarEspecialidadeEMedico`

Tipos de AVISO (não bloqueantes):
- **CNS_INVALIDO** — CNS do paciente preenchido sem 15 dígitos após normalização, a menos **ou a mais** (não bloqueia a importação); o valor errado **não é gravado** (recomendação 26, 19/10/2026 — o antigo `CNS_INCOMUM`, para mais de 15, foi incorporado aqui). Linha sem CNS válido não apaga o CNS que o paciente já tem: `AtendimentoImportacaoService.deveTrocarCns` só troca quando a linha traz CNS e ele não é pior que o gravado (DV errado não substitui CNS válido — recomendação 27). CNS **vazio** não gera aviso (Decisão 13, 16/10/2026): com CPF o CNS não vai para o BPA-I, e paciente sem CPF já exige o CNS (`CNS_OBRIGATORIO_SEM_CPF`)
- **CNS_DV_INVALIDO** — CNS do paciente com 15 dígitos mas dígito verificador errado (`CnsUtils.isDvValido`: primeiro dígito 1, 2, 7, 8 ou 9 e soma ponderada pelos pesos 15 a 1 divisível por 11 — algoritmo do Ministério da Saúde, sem consulta externa). AVISO quando há CPF (o CNS não vai para o BPA-I); para paciente sem CPF é o ERRO `CNS_OBRIGATORIO_SEM_CPF`. Também registrado no log de importação
- **RACA_INDIGENA** (ERRO desde 13/10/2026) — raça Indígena sem etnia; o BPA exige a etnia para raça 05 e descartaria o registro. Também rejeitado pelo `AtendimentoProcessor`
- **ETNIA_NAO_ENCONTRADA** (ERRO desde 13/10/2026) — raça Indígena com etnia fora da tabela oficial (mensagem: "Grafia da etnia \"X\" não reconhecida") (`EtniaUtils`, por nome ou código). Também rejeitado pelo `AtendimentoProcessor`
- **FORMATO_LEGADO_ESPECIALIDADE_MEDICO** — planilha antiga com coluna "Especialidade/Médico" combinada numa única célula; separado automaticamente na importação
- **COLUNA_SEM_CABECALHO** — coluna com dados mas com o cabeçalho vazio (valor "coluna E (ex.: \"CARDIOLOGIA\")"); não é lida na importação. A correção é sempre na planilha (escrever o nome no cabeçalho) — não há nome para cadastrar como alias em Configurações; a tela de estrutura destaca isso num quadro vermelho
- **CEP_FORA_DE_MS** — município encontrado na tabela de MS com CEP de 8 dígitos que não começa com 79 (`CepUtils.isForaDeMsComMunicipioDeMs`); nesse caso o CEP não é usado para o IBGE e passava sem conferência (decisão de 16/10/2026). Também no log de importação
- **NUMERO_FORA_DO_PADRAO** — número do endereço que não é número de imóvel (dígitos com letra opcional: 100, 12A, 12-B) nem forma de "sem número": até 5 caracteres vai como está (ex.: "X", "N/A"); com mais de 5 caracteres vai o número do começo da célula (também depois de Nº/KM; "100 apto 201" → 100) ou SN (`NumeroUtils`), com aviso mostrando o valor enviado. Também no log de importação
- **COMPLEMENTO_CORTADO** — complemento que não cabe em 10 caracteres mesmo abreviado (`EnderecoUtils.complemento`), cortado na palavra; mostra o que vai no BPA-I. Bairro cortado **não** gera aviso (Decisão 23, 16/10/2026). Também no log de importação
- **BAIRRO_IGUAL_MUNICIPIO** — bairro com o mesmo nome do município do paciente (ignorando acento, caixa e UF) — provavelmente a cidade na coluna errada. Também no log de importação
- **LOGRADOURO_NAO_RECONHECIDO** — coluna "Cód. Logradouro" com código fora da tabela DNE ou texto que não é tipo de logradouro, quando o endereço também não começa com um tipo; o gerador usa 081 (Rua). Também no log de importação
- **TELEFONE_SEM_DDD** / **TELEFONE_INVALIDO** — telefone com 8–9 dígitos (sem DDD — decisão de 14/10/2026: aviso, sem adivinhar o DDD; título "Telefone fora do padrão", mensagem pede DDD + número e avisa que, sem correção, vai em branco) ou não reconhecido (`TelefoneUtils`); o BPA-I sai com o telefone em branco (campo opcional). Também no log de importação
- **COLUNA_OPCIONAL_AUSENTE** — coluna opcional (`COD_LOGRADOURO`, `SITUACAO_RUA`, `PACIENTE_SEM_CPF` ou `TIPO_ZONA` — esta desde 14/10/2026, porque o tipo de zona não vai para o BPA-I e a planilha sem ela era bloqueada) não encontrada no cabeçalho; mensagem específica por campo (`ValidacaoPlanilhaService.mensagemColunaOpcionalAusente`) explica o fallback usado
- **SITUACAO_RUA_INVALIDA** — coluna "Situação de Rua" presente mas valor da célula não reconhecido (aceita S/N, Sim/Não, 1/0 via `SimNaoUtils`) — será enviado "N" na remessa
- **SITUACAO_RUA_VAZIA** — coluna "Situação de Rua" presente com a célula vazia: "será importada em branco" (vai branco no BPA-I). Também no log de importação. "Paciente sem CPF" com a célula vazia **não gera aviso** (20/10/2026 — o antigo `PACIENTE_SEM_CPF_VAZIO` foi removido): com o CPF preenchido e válido a importação grava "N"; com o CPF vazio já é `CPF_AUSENTE`, e CPF inválido já é erro de CPF
- **CAMPO_ANTES_DA_VIGENCIA** — "Situação de Rua" = Sim em atendimento de competência anterior a 12/2024, ou "Paciente sem CPF" = Sim antes de 07/2026 (vigência dos campos no layout — `VigenciaLayoutUtils`; Decisão 26, 16/10/2026): o campo vai em branco no BPA-I. Só com "Sim" — "Não" em branco não perde informação. Valor = campo + competência (agrupa). Também no log de importação
- **CPF_COM_NOMES_DIFERENTES** — mesmo CPF de paciente com nomes diferentes (sem CPF: mesmo CNS — recomendação 68) (comparados por `TextoUtils.chaveNome`: sem acento, caixa ou espaços repetidos), na planilha ou em relação ao nome já gravado (`ValidacaoPlanilhaService.comNomePacientePorCpf`, ligado pelo `MainController`). Decisão 12 (16/10/2026): AVISO — um só paciente é gravado, com o nome da última linha. Um aviso por linha do CPF, valor `CPF … — "NOME" (linhas …) × "OUTRO" (linha …)`. Na importação, `buscarOuCriarPaciente` avisa quando o nome cadastrado difere do da linha (para paciente sem CPF, a mensagem cita o CNS)
- **DATA_FORA_DO_ESPERADO** — data do atendimento futura ou com mais de 2 anos (`DateUtils.dataAtendimentoForaDoEsperado`, `ANOS_ATENDIMENTO_ANTIGO`) — provável ano digitado errado, que levaria o atendimento para outra competência (recomendação 4, 19/10/2026). Valor `dd/MM/aaaa — futura` / `— com mais de 2 anos`; a mensagem mostra a competência em que o atendimento entra. Também no log de importação. "Hoje" vem de `DateUtils.hoje()`, que os testes fixam em 2026-10-19 pela propriedade `fillbpai.hoje` (surefire, `pom.xml`) — testes com datas fixas não quebram com o passar do tempo
- **NOME_PACIENTE_LONGO** — nome do paciente com mais de 30 caracteres (tamanho de `prd-nmpac`); valor `"NOME" → "COMO SAI NO BPA-I"`, para quem quiser abreviar na planilha (recomendação 29, 19/10/2026). Também no log de importação
- **NOME_PACIENTE_SUSPEITO** — nome sem letras, com números, com símbolos, com uma palavra só ou de recém-nascido sem nome ("RN DE …", caso real, aceito) (`NomePacienteUtils.motivoSuspeito`; recomendação 30, 19/10/2026). Também no log de importação
- **PACIENTE_SEM_CPF_INVALIDO** — coluna "Paciente sem CPF" presente mas valor da célula não reconhecido (mesmas regras de `SimNaoUtils`) — valor será derivado automaticamente a partir do CPF do paciente
- **ESTABELECIMENTO_SEM_CODIGO** — célula "Estabelecimento" preenchida mas sem separador "código - nome" reconhecido; a importação tenta vincular por nome a um estabelecimento já cadastrado, senão o atendimento fica sem estabelecimento
- **ESTABELECIMENTO_AUSENTE** — célula "Estabelecimento" vazia, só com o separador (`-`, `—`) ou código zero (`StringUtils.isEstabelecimentoNaoInformado`); o atendimento fica sem estabelecimento. Valor fixo "não informado" (agrupa todas as linhas). Também registrado no log de importação pelo `AtendimentoProcessor`
- **ESTABELECIMENTO_SEM_NOME** — célula "Estabelecimento" só com o código (`1234567`, `12345 -`): vincula se o código já estiver cadastrado, sem apagar o nome; senão o atendimento fica sem estabelecimento (aviso no log de importação). O código do estabelecimento é sempre numérico: `StringUtils.separarCodigoENome` só aceita como código o que vem antes do primeiro hífen se for só dígitos (até 10) — texto antes do hífen (`UBS - CENTRO`, `HOSPITAL X - UNIDADE 2`) é parte do nome e cai em `ESTABELECIMENTO_SEM_CODIGO`
- **CNS_PROFISSIONAL_NAO_CADASTRADO** — grafia de médico não encontrada em Configurações → CNS de Médicos; um aviso por linha, com o mesmo `valor` para a grafia (agrupada sem acento/caixa) — a tela e o log juntam as linhas. Se o mesmo CPF tem CNS conhecido (outra grafia cadastrada na planilha, ou `Medico.cns` no banco — `MainController` passa a consulta via construtor `ValidacaoPlanilhaService(Function<String,String>)`), diz que o CNS será herdado e sugere cadastrar o apelido; senão, avisa que a geração do BPA-I ficará bloqueada
- **HORA_INVALIDA** — hora de atendimento preenchida mas não reconhecida por `TimeUtils` (ex.: "-", "--:--"; aceita HH:mm, H:mm, HH:mm:ss, HHmm, HH.mm e o formato com "h": 8h30, 08h30, 8h30min, 14h). Célula data+hora na coluna de horário é lida pela hora (`ExcelImportService.getHora`; só data, hora 00:00, continua virando aviso); o atendimento é importado sem hora (a hora não vai para o BPA-I) e `AtendimentoProcessor` registra aviso no log de importação em vez de descartar a linha

Leitura de células (`ExcelImportService.getString`): fórmulas são lidas pelo resultado em cache (não pelo texto da fórmula; fórmula com erro → vazio) e o espaço não separável U+00A0 é tratado como espaço comum, em todas as colunas.

O botão **"Analisar Planilha"** (topBar) permite validar sem importar; o botão "Importar Planilha" não fica fixo na UI — aparece dentro do diálogo de resultado quando não há erros bloqueantes.

**Ciência dos avisos** (20/10/2026, `MainController.CienciaAvisos`): na janela da análise com botão de importar, cada grupo de aviso (TitledPane do bloco âmbar) e cada item dos blocos verdes (colunas opcionais, formato legado) tem um "Ciente" no cabeçalho, à direita do título. O "Ciente" só é habilitado depois que o painel é aberto; "Importar Planilha" fica desabilitado até todos estarem marcados (texto ao lado: "Marque Ciente em todos os avisos para liberar a importação — X de Y" / "✓ Ciência de todos os avisos"); o chip do grupo ganha ✓. Sem "marcar todos". Títulos dos blocos: "marque Ciente para liberar a importação". Na janela com erros não há "Ciente" (os títulos dizem "não exigem correção"). O log de importação termina com a seção "=== CIÊNCIA DOS AVISOS ===": grupos com ✓, data/hora e a frase "A marcação indica que os avisos foram lidos; não indica que os dados foram verificados." Planilha sem avisos nem blocos verdes importa direto, sem essa seção.
O log da análise só é gravado pelo botão "Salvar Log TXT", no local escolhido pelo usuário (19/10/2026 — antes era salvo sempre em `database/log_erros_validacao_<planilha>.txt`, sem ser lido pelo programa). O log de **importação** continua salvo automaticamente, **um arquivo por importação** (20/10/2026): `logs/log_importacao_<planilha>_<aaaa-MM-dd_HHmm>.txt` (com `_2`, `_3`… se repetir) — pasta própria, separada do banco (`MainController.PASTA_LOGS`); logs gravados antes em `database/` são movidos para `logs/` ao abrir o programa (`HistoricoLogsService.migrarDe`, sem sobrescrever) — reimportar a mesma planilha não apaga o log anterior. O botão "Ver Log Importação" abre o **histórico** (`HistoricoLogsService` + `MainController.exibirLogSalvo`): lista da mais recente para a mais antiga (data/hora, planilha, linhas, avisos — tirados do cabeçalho do log; logs antigos sem cabeçalho usam o nome e a data do arquivo), busca pelo nome da planilha, log selecionado à direita com "Copiar log"; a mais recente já vem aberta. Lê a pasta, então funciona depois de reiniciar (antes procurava `database/log_importacao.txt`, que não era mais gravado, e dizia "Nenhum log de importação encontrado").

Exibição agrupada: `ErroValidacao` tem campo opcional `valor` (o que varia entre ocorrências — valor da célula entre aspas, nome do paciente ou do médico), separado do `detalhe`. `AgrupamentoValidacao` mantém título legível, explicação e prioridade por tipo e agrupa por tipo (ERRO antes de AVISO) e, dentro do tipo, por valor (`valor — N linhas: ...`). Usado pela tela do "Analisar Planilha" (`MainController.criarBlocoSeveridade`: chips de filtro por tipo + `TitledPane` por grupo) e pelo log TXT (`gerarLogTxt`). Ao criar um tipo novo de erro/aviso, cadastrar título/explicação/prioridade em `AgrupamentoValidacao` e preencher o `valor`.

### Fluxo de Importação
1. `ValidacaoPlanilhaService` — valida regras bloqueantes (CNS, CEP, CPF). Se erros → bloqueia importação
2. `ExcelImportService` — lê Excel, retorna `LinhaImportacaoDTO`
3. `AtendimentoProcessor` — valida/normaliza (CNS, datas, etc.), retorna lista de avisos
4. `AtendimentoImportacaoService` — processa normalmente: findOrCreate para entidades, resolve IBGE via `IbgeUtils`, resolve CNS profissional via `CnsProfissionalUtils` (por nome), persiste atendimento

### Utilitários
- `IbgeUtils` — resolve código IBGE em cascata: 1) CSV por nome do município, 2) cache pré-carregado do banco (CEP → codigoIbge de `Endereco`), 3) APIs de CEP na internet como último recurso — ViaCEP; se falhar ou não tiver o CEP, BrasilAPI e depois OpenCEP (reservas). Cache negativo só quando todas respondem "não encontrado"; falha de rede não é guardada (próxima importação tenta de novo). HTTP simulável nos testes (`usarBuscadorHttpParaTeste`). `preCarregarCacheDb()` chamado em `AtendimentoImportacaoService` antes do loop de importação.
- `CnsProfissionalUtils` — resolve CNS do profissional por **nome** (normalizado: uppercase, sem acentos). Fonte única: `dados/medicos_cns.csv` (classpath + arquivo externo `src/main/resources/dados/medicos_cns.csv`, formato `nome;cns`). Sem consulta ao DATASUS. Busca por nome é intencional (o mesmo médico chega com grafias diferentes; apelidos ligam as grafias ao CNS). Na importação (`AtendimentoImportacaoService.resolverCnsProfissional`): nome encontrado → CNS no atendimento e em `Medico.cns` (aviso se diferir do CNS já associado ao CPF); nome não encontrado mas `Medico.cns` conhecido → CNS herdado do mesmo CPF, com aviso para cadastrar a grafia como apelido (decidido no fim da planilha, então vale mesmo se a grafia cadastrada vier em linha posterior); nenhum dos dois → aviso "CNS do profissional não encontrado".

**Todas as linhas da planilha devem ser importadas** (decisão de 09/10/2026) — nenhuma linha é descartada sozinha:
- **Tudo ou nada**: qualquer linha com erro na importação cancela a planilha inteira (rollback, nada gravado), com a lista de linhas na mensagem ("Importação bloqueada — N linha(s) com erro; nenhuma linha foi importada").
- **Conferência de linhas** (`AtendimentoImportacaoService.conferirLinhasImportadas`): antes do commit, linhas com dados da planilha = linhas gravadas = atendimentos distintos; se não bater, cancela. O log de importação mostra "Linhas da planilha: N · Importadas: N (X novas, Y atualizadas) ✓ conferido" (`ImportacaoResultado.linhasPlanilha/totalNovos/totalAtualizados`).
- **Linhas vazias** (só formatação, espaços, conteúdo apagado — `ExcelImportService.isLinhaVazia`) são ignoradas igualmente na análise, na importação e na contagem.
- **Duplicidade dentro da planilha** (`DetectorDuplicidade`, mesma chave na análise e na importação: paciente + médico + data + SIGTAP): mesmo horário (ou os dois sem horário) → ERRO **LINHA_DUPLICADA** (uma linha sobrescreveria a outra); horário diferente → AVISO **SUSPEITA_DUPLICIDADE**, importadas como atendimentos separados. A chave de deduplicação no banco (`AtendimentoBPAiRepository.buscarDuplicata`) inclui o horário — reimportar a mesma planilha continua atualizando em vez de duplicar.
- A análise cobre todo motivo de rejeição da importação: **PACIENTE_AUSENTE** (nome vazio), **DATA_NASCIMENTO_INVALIDA** (formato) e **LINHA_ILEGIVEL** (falha ao ler a linha, antes ignorada em silêncio) são ERROs.

Importação grava linha a linha (`flush` por linha). Erro do banco numa linha marca a transação única da planilha para rollback — a importação é então cancelada com mensagem explícita ("nenhuma linha foi importada"), em vez de o commit desfazer tudo em silêncio com o log dizendo "Sucesso".
- `CnsUtils` — processa/valida CNS de pacientes: sem 15 dígitos (a menos ou a mais) → aviso `CNS_INVALIDO` e CNS vazio (não grava o valor errado — recomendação 26); DV errado → aviso `CNS_DV_INVALIDO`
- `CepUtils` — normalização de CEP
- `DateUtils` — conversão de datas em modo estrito (ver `DATA_INVALIDA`), `idadeNaData(nascimento, dataAtendimento)` (idade do BPA-I na data do **atendimento**, não na de hoje) e `incoerenciaNascimento`
- `LogradouroUtils` — tipo de logradouro pela **tabela DNE** `dados/tipos_logradouro.csv` (393 tipos, código de 3 dígitos — fornecida pelo usuário em 15/10/2026). Linha começando com `#` é comentário: **023 (Campo) desativado** em 19/10/2026 — "Campo …" fica no endereço e o código 023 na coluna não é reconhecido (reativar tirando o `#`). `resolver(endereco)`: tipo no começo do endereço (sem acento/caixa; vale o tipo mais longo que casar, desde que sobre um nome — "Avenida Central" → 008 + "Central"; abreviações R, AV, TV/TRAV/TRV, AL, PC/PCA, EST/ESTR, ROD, seguidas de espaço ou pontuação) → código, e o prefixo sai do endereço. `codigoDaColuna(celula)`: código da tabela (1–3 dígitos, completado com zeros) ou nome/abreviação do tipo. Aplicado no `AtendimentoProcessor.normalizarLogradouro`: prefixo do endereço vence a coluna; endereço cortado em 30 **depois** de tirar o prefixo e na última palavra inteira (`StringUtils.limitarNaPalavra`). Antes só Rua/Avenida/Travessa eram reconhecidas, texto na coluna virava `000` ou cancelava a importação, e o corte vinha antes do prefixo
- `EnderecoUtils` — bairro (seq 34, 30) e complemento (seq 32, 10), campos opcionais: valores de preenchimento (`-`, `X`, `0`, `N/A`, `NÃO INFORMADO`, `SEM`…) → vazio; bairro sem a palavra "Bairro" no começo e cortado na palavra; complemento que não cabe em 10 é abreviado (Apartamento/Apto → AP, Bloco → BL, Casa → CS, Fundos → FDS, Quadra → QD, Lote → LT, Sala → SL, Conjunto → CJ, Edifício → ED, Andar → AND) e cortado na palavra; o que cabe fica como foi digitado. Usado na importação e no gerador (dados antigos). Antes os dois eram só cortados no meio da palavra ("Apartamento 201" → "Apartament")
- `NumeroUtils` — número do endereço (BPA-I seq 33, 5 posições): vazio e formas de "sem número" (S/N, SN, SEM NUMERO, SEM Nº, 0, e só traço `-` — 19/10/2026) → `SN` sem aviso (decisão de 16/10/2026, padrão do layout); número de imóvel (dígitos com letra opcional) → como veio; outro valor de até 5 caracteres → como veio, com aviso; mais de 5 → número do começo (até 5 dígitos) ou `SN`, com aviso. Usado na importação e no gerador (dados antigos). Antes o número era só cortado em 5 ("SEM NUMERO" → "SEM N", "123456" → "12345")
- `TelefoneUtils` — normaliza o telefone: fica com o **primeiro** número da célula (separadores `/`, `;`, `,`, `|`, " e ", " ou "), tira o DDI `+55`/`55` e o `0` de longa distância; 10 ou 11 dígitos = válido (gravado só DDD + número), 8–9 = sem DDD, resto = inválido (gravado vazio). Antes o gerador ficava com os 11 primeiros dígitos ("+55 67 …" → "5567…") e uma célula com vários telefones passava dos 20 caracteres da coluna e cancelava a importação
- `CidUtils` — extrai o código CID-10 da célula (letra + 2 dígitos + subcategoria opcional, com ou sem ponto): "CID I10" e "I10 - Hipertensão" → `I10`, "I10.9" → `I109`; nenhum código ou mais de um → `null`. A importação grava só o código (antes uma célula com descrição passava dos 20 caracteres da coluna e cancelava a importação); o gerador usa o mesmo extrator para dados antigos
- `EtniaUtils` — resolve código oficial de etnia indígena (4 caracteres, numérico ou alfanumérico com prefixo "X") via `dados/etnias_indigenas.csv` (classpath, somente leitura — **a tabela não deve ser alterada**). Aceita o nome (sem acento/caixa; nomes alternativos entre parênteses da tabela), o nome com parênteses na célula ("Terena (Tereno)") e o próprio código digitado ("0207", "207" → 0207, "X290"), conferido contra a tabela. Grafias que a tabela não tem (ex.: "Kinikinau" — a tabela usa KINIKINAWA) continuam não encontradas
- `NomePacienteUtils` — nome do paciente (seq 19, 30 posições): `padronizar` (maiúsculas, espaços repetidos reduzidos, acentos mantidos — Decisão 14 em aberto), `cortadoNoBpa`, `motivoSuspeito`. Aplicado na importação (o nome é gravado padronizado) e no gerador (dados antigos)
- `SexoUtils` — sexo F/M/I (seq 11) a partir de F, M, I, Feminino, Masculino, Indeterminado, Fem, Masc, Mulher, Homem (sem acento, caixa ou ponto final); outro valor → `null` (erro na análise e na importação). O gerador usa a mesma conversão e cai em "F" só para dados antigos sem sexo válido
- `RacaUtils` — resolve código de raça/cor (2 dígitos, seq 21) por **palavra inteira** (Branca/Branco, Preta/Preto, Parda/Pardo, Amarela/Amarelo, Indígena/Índio/Índia) ou pelo código 01–05 (1–5); antes era por trecho e "Indeterminado"/"Indefinida" viravam Indígena. Texto com mais de uma raça ou com negação ("Não", "Sem") não é reconhecido. Usado por `ValidacaoPlanilhaService`/`AtendimentoProcessor` (bloqueia se ausente/não reconhecida) e por `GeradorBPAiService` (fallback branco — Default oficial de `prd-raca` no layout — só para dados legados; "99" é código descontinuado)
- `SimNaoUtils` — normaliza campos S/N (aceita S/N, Sim/Não, 1/0) usado por `prd_situacao_rua` e `prd_sem_cpf`; mesma lógica usada tanto na análise quanto na importação
- `VigenciaLayoutUtils` — vigência dos campos novos do layout (`prd_situacao_rua` desde a competência 12/2024, `prd_sem_cpf` desde 07/2026); competência = mês da data do atendimento. Usado pelo gerador (branco antes da vigência) e pelos avisos `CAMPO_ANTES_DA_VIGENCIA`

### Geração BPA-I
- Geração individual (filtrada por especialidade/médico selecionados)
- Geração completa (atendimentos do mês de competência selecionado)
- **Folha e linha (20/10/2026 — regra única):** `GeradorBPAiService.numerarFolhas` numera a competência inteira: atendimentos em ordem especialidade → médico → data → hora; cada especialidade + médico começa uma folha nova (001, 002…); folha nova também a cada 99 linhas (`prd-seq` 01..99, nunca volta a 01 na mesma folha); mais de 999 folhas bloqueia (`prd-flh` 001..999). A geração parcial usa a mesma numeração (calculada sobre a competência inteira) e escreve só o médico. O header leva o total de folhas distintas do arquivo (antes o parcial informava o número de linhas). Depois de salvar o arquivo, `registrarRemessa` grava folha, linha e data/hora da remessa nos atendimentos enviados (numa transação); a tabela mostra as colunas **Folha**, **Linha** e **Remessa** ("—"/"não enviada" antes do envio; folha gravada sem remessa — do antigo "Definir Folha" — não é mostrada). Gerar de novo atualiza. A importação não define mais a folha (antes herdava a do médico), e o botão "Definir Folha" foi removido. Cancelar a escolha do arquivo não grava nada nem mostra "gerado com sucesso"
- Competência para geração: selecionada clicando no badge `📅 Competência: MM/YYYY` da barra fixa inferior; auto-detectada da primeira carga de dados se não definida manualmente
- `GeradorBPAiService.gerarArquivoCompletoComFileChooser(window, competenciaAtendimento)` recebe competência no formato `YYYYMM` do mês de atendimento e filtra por `YEAR/MONTH(dataAgendamento)`
- Seq 10 (prd-cnspac): o paciente é identificado por um documento só — CPF (seq 38) ou CNS (layout 2026, observação 2; o programa BPA critica os dois juntos, versões 04.06/04.07). Com CPF → 15 brancos; sem CPF ("Paciente sem CPF" = Sim) → CNS do paciente (15 dígitos, obrigatório desde a importação)
- Seq 12 (prd-ibge): código IBGE real do endereço, truncado para 6 dígitos
- Seq 13 (prd-cid): código CID-10 sem ponto (`CidUtils.extrair`), brancos se vazio — antes o texto era cortado em 4 caracteres ("I10 - Hipertensão" → "I10H")
- Seq 30 (prd_lograd_pcnte): código DNE do tipo de logradouro (`LogradouroUtils`); não reconhecido → 081 (Rua), decisão de negócio de 11/09/2026. Seq 31 (prd_end_pcnte): endereço sem o tipo, até 30 caracteres. Seq 33 (prd_num_pcnte): `NumeroUtils` — vazio/sem número → `SN`. Seq 32 e 34 (complemento e bairro): `EnderecoUtils`
- Seq 35 (prd_ddtel_pcnte): DDD + número normalizado por `TelefoneUtils` (dados antigos também), brancos à direita; sem DDD ou inválido → 11 brancos
- Tipo de zona: não existe no layout 2026 — só gravado (cortado em 50 caracteres) e mostrado na tabela
- Seq 14 (prd-idade): idade na data do atendimento (`DateUtils.idadeNaData`) — antes era calculada na data de hoje e a remessa gerada depois de um aniversário saía com um ano a mais
- Seq 22 (prd-etnia): código da etnia **só quando a raça é Indígena (05)**; nas demais raças, 4 brancos mesmo com a etnia preenchida (regra do layout — vale também para dados já gravados)
- Seq 38 (prd-cpf-pcnte): CPF do paciente, 11 dígitos — é aqui, não na seq 10, que o CPF entra no registro. Sem CPF → 11 brancos (antes saía `00000000000`, CPF que o programa BPA critica e descarta — versão 04.03)
- Seq "38" duplicado no layout oficial (prd_situacao_rua): usa `atendimento.situacaoRua` (situação no momento do atendimento, 16/10/2026; reserva: `paciente.situacaoRua` legado, para atendimentos antigos); coluna ausente → "N" (regra de coluna opcional ausente, gravado no atendimento); coluna presente com a célula vazia (`""`) → **branco** (16/10/2026 — o layout manda branco quando não há informação). Atendimento de competência anterior a 12/2024 → **branco** (campo ainda não existia no layout — Decisão 26)
- Seq 39 (prd_sem_cpf, novo no layout 2026): usa `atendimento.pacienteSemCpf` quando a planilha trouxe a coluna "Paciente sem CPF"; coluna ausente (`null`) → deriva da presença do CPF do paciente (CPF preenchido → "N", CPF vazio ou chave interna de paciente sem CPF → "S"); coluna presente com a célula vazia → a importação grava "N" quando o CPF está preenchido (20/10/2026); `""` → **branco** só em atendimentos gravados antes disso. Atendimento de competência anterior a 07/2026 → **branco** (vigência do campo — Decisão 26)
- Regra geral das colunas opcionais S/N (16/10/2026): coluna ausente → aviso único `COLUNA_OPCIONAL_AUSENTE` e o padrão de cada campo; coluna presente com célula vazia → `ExcelImportService.getOpcional` devolve `""`; situação de rua: aviso por linha (`SITUACAO_RUA_VAZIA`) e branco no BPA-I; paciente sem CPF: "N" pelo CPF preenchido, sem aviso (20/10/2026)
- **Pré-validação obrigatória**: `GeradorBPAiService.validarCnsProfissional()` e `validarIbge()` bloqueiam a geração se qualquer atendimento estiver sem CNS do profissional ou sem código IBGE do município do paciente, exibindo relatório com médico/paciente/data de cada ocorrência

| **Explorer** | Haiku | Buscas rápidas no codebase, lookups, exploração de arquivos |

### Regras do Time
- Orchestrator é o ponto de entrada — recebe a tarefa e decide quem executa
- Implementer segue TDD: escreve teste falhando primeiro, depois implementa
- Explorer é usado para buscas rápidas antes de implementar (entender contexto)
- Tarefas independentes devem rodar em paralelo quando possível

## Regras de Negócio Principais
- Layout BPA-I: campos posicionais com tamanho fixo (351 chars de conteúdo por registro + CRLF = 353)
- Header: 132 chars
- Campos NUM opcionais: brancos quando vazio, zeros à esquerda quando preenchido
- Campos ALFA: espaços à direita até completar tamanho, e corte no tamanho do campo (`GeradorBPAiService.padRightSpaces`) — um valor maior nunca desloca o registro
- Codificação do arquivo de saída: ISO-8859-1
- Documento de referência do layout: `data/Layout_Exportacao_BPA_2026.pdf` (substitui `Layout interface texto do BPA.pdf`, que não existe mais no repositório)
